# API ↔ DB Reconciliation Report

Дата аудита: 2026-09-30. Сверка живых ответов Instagram Graph API (v25.0)
против строк рабочей БД (`data/instagram_bot.db`). Инструмент:
`scripts/verify_api_vs_db.py` (read-only по БД).

## Методика

Для каждого из 6 аккаунтов сверялись:

1. **Профиль** — `followers_count` из `/me` против `accounts.current_followers`
   (легаси-фолбэк: последний `daily_stats.followers`).
2. **Дневные инсайты** — `reach`, `follower_count` (old-format values[]) и
   `views`, `accounts_engaged` (new-format, per-day total_value) против
   `daily_stats` построчно.
3. **Публикации** — `like_count`, `comments_count` из `/media` и
   `reach/saved/shares/total_interactions/views` из `/media/{id}/insights`
   против `posts` (до 15 свежих постов на аккаунт).
4. **Сторис** — активные `/stories` и их инсайты против `stories`.

## Найденные и устранённые расхождения

### 1. Сдвиг `views`/`accounts_engaged` на один день (устранено)

**Симптом:** значение окна `[D+1 00:00Z, D+2 00:00Z)` оказывалось в строке `D`.

**Root cause:** `InstagramClient.collect_full_snapshot` строил per-day окна от
исходного `since` без выравнивания по полночи UTC. Зонд-тесты доказали, что
Instagram возвращает `total_value` **точно за запрошенное окно**:

| Окно запроса | views (roomfineartwinedine, 28.09) |
|---|---|
| `[28.09 07:00Z → 29.09 07:00Z)` (точный бакет IG) | 5216 |
| `[28.09 00:00Z → 29.09 00:00Z)` (полночь UTC) | 3625 |
| `[28.09 18:27Z → 29.09 18:27Z)` (невыровненное) | 1591 |

**Фикс:** `instagram/client.py` — окна принудительно нормализуются к
00:00 UTC (`replace(hour=0, ...)`); регрессионный тест
`test_snapshot_day_windows_are_midnight_aligned`.

**Примечание:** day-бакеты IG проходят `[D 07:00Z → D+1 07:00Z)`, а
`end_time` в old-format values[] — это **начало** бакета (проверено по
растущему значению текущего дня). Разметка `end_time.date()` в коде
корректна и согласована между всеми метриками строки.

### 2. Легаси-строки: `follower_count = 0` при фактическом значении (устранено синхронизацией)

Старые строки (до внедрения `metrics_present`) содержали `follower_count = 0`
там, где API отдавал 12–13 — классическая проблема «нет метрики → 0».
Механизм повторной выборки для дней с `metrics_present IS NULL` в окне
`DATA_SYNC_WINDOW_DAYS` перезаписал их корректными значениями ✅.

### 3. Аккаунты без данных (устранено сидингом)

До аудита в БД было 3 из 6 аккаунтов `.env`. Сидинг при старте (`seed_accounts`)
добавил `cms.space`, `roomcatering2`, `room.airport`; синхронизация наполнила
их данными за 30 дней.

## Ожидаемые и некритичные эффекты (не баги)

- **Текущий день** всегда расходится с API в момент сверки: метрики
  накапливаются. Синхронизация доводит их при следующем цикле.
- **`roomcatering2` — статус `partial`:** Instagram не возвращает дневной
  прирост подписчиков для крошечного аккаунта (11 подписчиков). Обработано
  корректно: счётчик всё равно сохранён, причина записана в
  `accounts.last_sync_error`, отражена в sync-health уведомлениях.
- **`TelegramConflictError` при smoke-тесте:** второй экземпляр бота с тем же
  токеном уже работает (прод-инстанс) — для прода это норма, локально нужно
  останавливать прод перед запуском.
