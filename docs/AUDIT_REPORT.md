## Найденные и исправленные проблемы

### 1. Сдвиг дневных метрик views/accounts_engaged на один день 🔴 → ✅
`collect_full_snapshot` строил per-day окна от исходного `since` без
выравнивания по полночи. Instagram возвращает `total_value` точно за окно →
невыровненные границы смещали значения на день. Зонд-тесты подтвердили
(см. `API_DB_RECONCILIATION.md`). **Фикс:** нормализация окон к 00:00 UTC в
`instagram/client.py` + регрессионный тест.

### 2. Перетирание provenance сторис 🟡 → ✅
`crud.update_story_insights` заменял `metrics_present` списком последнего
ответа API — частичное обновление теряло сведения о ранее виденных метриках.
**Фикс:** кумулятивное объединение множеств.

### 3. `json.loads` без обработки ошибок в `calculate_stories_summary` 🟡 → ✅
Повреждённые метаданные роняли генерацию отчёта. **Фикс:** безопасный парсинг
с откатом на пустое множество.

### 4. Пустой ответ AI → `TelegramAPIError: message text is empty` 🟡 → ✅
Был в логах 23.09. Уже закрыт в рабочем дереве fallback-текстом
(`test_empty_message_is_replaced_with_fallback`), проверено аудитом.

### 5. NameError `_day_end` / `resolve_period` в логах 23.09 🔴 → ✅
Бот падал при генерации отчётов и дайджестов. Закрыто в рабочем дереве
(функции определены + regression-тесты `test_day_end_is_available...`,
`test_resolve_period_supports_default_week`).

### 6. Схема БД отставала от моделей 🟡 → ✅
Отсутствовали `sync_leases`, `metrics_present`, `insights_present`,
`current_followers`, `status/claimed_at/expires_at` уведомлений.
Миграции `database/engine._apply_lightweight_migrations` проверены на копии
(0 потерянных строк, integrity ok) и применены к рабочей БД.

### 7. Легаси-данные «нет метрики → 0» 🟡 → ✅
`follower_count = 0` при фактических 12–13 в старых строках. Механизм
повторной выборки дней с `metrics_present IS NULL` перезаписал значения.

### 8. 3 из 6 аккаунтов отсутствовали в БД 🟡 → ✅
Сидинг + полная синхронизация; все 6 аккаунтов актуальны.

### 9. Молчаливая обрезка AI-контекста → ложные сомнения в достоверности отчёта 🔴 → ✅
Пользователь спросил у бота «насколько данные в отчёте реальны», и AI-чат
ответил «в детализации данные только до 14 сентября, показано 13 из 17
постов → отчёт неполный, проверить нельзя». Причина: `format_context_for_ai`
молча резал контекст (`daily[:14]`, `publications[:12]`) без единого маркера —
модель видела усечённые данные и интерпретировала это как неполноту самого
отчёта. Реальные цифры при этом были полными и верными.
**Фикс:** все дни/публикации/сторис попадают в контекст; при переполнении
бюджета — только явные маркеры «…[опущено N из M …]» + дисклеймер в шапке +
правило в `CHAT_SYSTEM_PROMPT` (маркер ≠ неполнота отчёта) + маркированная
обрезка в `chat_with_context`. Регрессионные тесты + чек `ai_context_complete`
в аудит-харнесе (30 проверок).

### 10. Разрыв сообщений посреди слова («ком/ментариев») 🟡 → ✅
`send_long_text` резал по 4096 символам. **Фикс:** `split_message_text` режет
по границам строк; hard-split только для сверхдлинных строк.

### 11. Пустой AI-анализ из-за малого бюджета токенов 🔴 → ✅
При живой проверке обнаружено: `analyze_account` завершался с
`finish_reason=length` — reasoning-модель тратила все 700 completion-токенов
на скрытые reasoning-токены, видимый ответ был пуст → тихий fallback. Бюджеты
550–900 были подобраны без учёта reasoning.
**Фикс:** `REPORT_MAX_COMPLETION_TOKENS = CHAT_MAX_COMPLETION_TOKENS = 2400`.

### 12. Репосты фото не запрашивались у API («📤 0» и гэп +202) 🔴 → ✅
У фото в отчётах стояло «📤 0», а AI писал «расхождение +202, причина не
подтверждена». Верификация прямым запросом к API: Instagram **возвращает
`shares` для IMAGE** (у фото 14.09 — 195 репостов). Причина: `shares`
отсутствовал в `MEDIA_METRICS_MAP["IMAGE"]` (у остальных типов был).
**Фикс:** добавлен `shares` в IMAGE-запросы и в `expected_metrics`;
`scripts/backfill_post_insights.py` дозаполнил 5 IMAGE-постов по всем
аккаунтам (0→195, 0→31, 0→15, 0→12, 0→4). Гэп взаимодействий упал с 214 до 21
(остаток — реальное поведение IG: `total_interactions` включает отдельно
не выгружаемые действия; теперь это честные единицы, а не сотни).

### 13. Двусмысленная формулировка «старые сторис с неизвестной полнотой» 🟡 → ✅
Модель трактовала её как «данные старые/ненадёжные». Заменено на «собраны до
внедрения учёта полноты (данные реальные, полнота метрик документально не
подтверждена)» в отчётах, AI-контексте и промптах.

## Проверено без замечаний

- **Отчёты:** день/неделя/месяц/произвольный/половина диапазона × 6 аккаунтов;
  каждый итог (рост подписчиков, %, тренд, reach/views/engaged, посты,
  ER, компоненты взаимодействий, interaction_gap, сторис) пересчитан
  независимым SQL — 0 расхождений; текстовые маркеры каждого блока на месте.
- **Сравнения:** halves-equal, 5-vs-1 (неравные), week-vs-week — обе стороны,
  per-day нормализация, available-days — всё сходится; пересекающиеся периоды
  отклоняются.
- **Граничные случаи:** будущие и перевёрнутые даты, пересечение периодов
  сравнения, пустой период, однодневный отчёт, битый текстовый ввод.
- **Запись в БД:** идемпотентные upsert'ы (двойной синк — 0 дублей),
  `delete_stale_posts` вызывается только при полной пагинации (защита от
  потери данных), `skip_insights` не затирает сохранённые инсайты, max-семантика
  для метрик сторис, уникальные констрейнты.
- **Актуальность данных:** freshness-кэш 48ч, tiered-refresh постов
  (hot/warm/cold), lease-блокировки с heartbeat, recovery осиротевших
  `SyncRun`, идемпотентные `NotificationDelivery`.
- **AI-слой:** модель `gpt-5.6-luna`, grounding-промпты, ограничение контекста,
  компактная история, fallback без `OPENAI_API_KEY`.
- **Надёжность:** global error-handler с уведомлением админа, ретраи клиента
  (rate-limit/5xx), `TokenExpiredError` → уведомление админу с cooldown,
  ротация логов, бэкапы SQLite с ретеншеном (проверены в smoke).
- **Безопасность:** `AdminMiddleware` (admin ID + username whitelist),
  `parse_mode=None` везде (нет injection через данные), `.env` не в git.

## Операционные замечания (без код-фиксов)

1. **TelegramConflictError при локальном запуске:** прод-инстанс бота уже
   работает с этим токеном. Перед локальным запуском останавливайте прод
   (иначе один из двух инстансов будет терять апдейты).
2. **`roomcatering2` остаётся `partial`:** Instagram не отдаёт дневной прирост
   подписчиков для аккаунта с 11 подписчиками. Это ограничение API, не бота;
   статус и причина корректно записываются и отражаются в sync-health.
3. **Текущий день** в отчётах может быть неполным до следующего синка
   (IG накапливает метрики) — отчёт честно помечает это блоком предупреждений.
4. **`.env` не содержит необязательных ключей** (таймауты, окна) — работают
   дефолты из `config.py`; при необходимости добавьте по `.env.example`.

## Инструменты аудита (сохранены в `scripts/`)

- `scripts/audit_reports.py --db <snapshot> [--accounts ...]` — генерация
  отчётов/сравнений из read-only снапшота + перекрёстный SQL-пересчёт
  (1350 проверок на6 аккаунтах).
- `scripts/verify_api_vs_db.py [--days N] [--accounts ...]` — живая сверка
  Instagram API против БД.
- `scripts/sync_check.py [--days N] [--accounts ...]` — одноразовая полная
  синхронизация + отчёт о статусе/здоровье.
